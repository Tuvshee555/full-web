# Lorentz AI chatbot: implementation report (2 November 2026)

Branch `chatbot-intelligence`, local only. Nothing merged, pushed or deployed. The Uudam project
was read only; no Uudam customer data, credentials or client prompts were copied.

## 1. What changed

| Area | Change |
| --- | --- |
| Conversation (the four held-out defects) | Delivery-time questions ("hed hongiin dotor irhe ve", "hezee irh ve", "Ulaangom ruu yvuulj boloh uu") answer the delivery policy before any product routing; "what do you sell" is always the numbered catalogue, also when the model lists products; person requests in Latin and Cyrillic ("hun bnu", "huntei yarimaar bn", "operator bnu", "ajiltantai holbogdoh", "huntei holboj ogooch", "chatbot bish hun heregtei") hand over at layer 0; "how long should I use it" with a product in play quotes the owner's FAQ or frequency and never the growth refusal |
| Mongolian handling | About 90 new Latin aliases (хоног, ирэх, ямар, зардаг, хэрэгтэй, явуулах, хадгалах, буруу, мөнгө, хөхүүл, нүд, "bnu", "za", "tiim" …), English product words (oil, pencil, brush, set), quantities glued to case endings ("2iig"), ordinal picks followed by a question ("2 dahi ni hed ve"); Latin "tiim"/"ugui" confirm or cancel a chat order |
| Model | gpt-4.1-mini is the default everywhere (`DEFAULT_AI_MODEL`, `resolveAiModel`); the migration writes it into the stored setting; a premium model is reachable only by the admin's explicit choice or a known `OPENAI_MODEL` |
| Product knowledge | Per-fact verification on every product (11 facts); storage and usage-frequency fields; the assistant quotes only verified facts; editing a fact clears its tick; the Knowledge tab shows verified / unverified / missing per fact |
| Reservations | 60-minute hold, one unpaid chat order per phone (advisory lock), 5 units per option, all owner-editable; per-order `expiresAt`; website checkout untouched |
| Expiry | Dual-query job (explicit deadline, legacy window), once-only claim, inline release before a chat order and on a stock shortfall, chat traffic triggers the sweep, secured `POST /api/jobs/expire-orders`, `vercel.json` daily cron, `JobRun` record shown in the admin |
| Hand-over | New reason `bulk_order`; the second-order refusal and bulk requests flag the chat for staff |
| Admin | One "AI Chatbot" section: Overview, Conversations (chats + callback requests), Knowledge, AI settings (model, budget, reservation policy), Analytics and costs, Activity (audit trail), Try it, Problems log. Old links redirect |
| Audit | `ChatAuditLog` for settings, FAQ, product facts and verification, takeovers, notes, chat orders, expiry runs |
| Evaluation | 215-conversation gate (299 turns) incl. both retired held-out sets; a fresh 66-conversation held-out set; spend cap per live run checked before every call |

Engine guards added around the model's reading: a word that fits several products answers for all
unless narrowed; a bare "үнэ хэд" with nothing in focus asks which product; an eye or skin reaction
is answered with stop/rinse/doctor before the model can label it.

## 2. Uudam engineering patterns reused (none of its data)

- Fail-closed cron authorization with a timing-safe secret compare (Uudam `isCronAuthorized`), daily
  Vercel cron plus an external scheduler for minute-level work.
- Lease + dedup per conversation, staff takeover that pauses the bot, automatic hand-back after
  silence, hand-over reasons and lead context (kept from the first round).
- Deterministic structured answers first, model-written prose behind a verifier, never silence.
- Held-out evaluation discipline and spend guards for live runs.

## 3. Lorentz-specific (the commerce adapter)

Catalogue and variant read, fact verification, purchase flow and chat orders, reservation policy and
expiry, checkout links, private order status, the product knowledge checklist. A future shop (MANAN)
keeps `handler.ts`, `turn.ts`, `textNorm.ts`, routing, model adapters, verifier, hand-over, budget,
audit and analytics, and replaces `catalogue.ts`, `productAnswerPlan.ts`, `commerce/*` and
`store-data.mjs`.

## 4. gpt-4.1-mini configuration

`src/chatbot/aiUsage.ts`: `DEFAULT_AI_MODEL = "gpt-4.1-mini"`; `resolveAiModel(adminChoice)` → the
admin's allow-listed choice, else `OPENAI_MODEL` if it has a known price, else the default. Used by
the understanding model, the writer, the OpenAI adapter, the analytics and system routes. Deterministic
fallback, daily budget, rate-limit handling, empty-completion logging and the no-silent-upgrade rule
are unchanged and verified (`scripts/test-chatbot-db.mjs`: over budget → 0 model calls, still a reply).

## 6. Remaining incorrect answers

- «Darhan hot, 3-r bag» (countryside address in Latin letters inside a chat order): not recognised,
  the draft does not advance (both runs). Aimag names are matched in Cyrillic only.
- «arisand turhsnii daraa zagatnaad bna» (itching after use): "zagatnaad" unknown; no stop/rinse/doctor
  reply and no hand-over (both runs).
- «serum bolon gel hoyulaa hed bolh ve», «serum ni yunaas butsen be»: wrong with rules only, right with the model.
- «nud ruu orchihloo yah ve»: right with rules, wrong at the live run with the model; fixed afterwards
  (aliases), confirmed by the gate and a unit check, not re-run live.
